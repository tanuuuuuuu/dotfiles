# clarify-request: 依頼明確化・聞き返し支援

社内で質問・依頼を受け取った人の「聞き返し」を支援する。
依頼文を構造化し、不足情報を特定し、そのまま送れる返信文案まで作る。

このチェックリストは「フェニックスチェックリスト」（CIA 由来とされる問題定義の質問集）を
Slack での聞き返し用に 7 観点へ蒸留したもの。観点を追加・変更するときは原典に立ち返って検討する。

## 入力

- 質問・依頼文の貼り付け（Slack メッセージ等）
- Slack スレッド URL の場合: Slack MCP ツールが使えるならスレッドを読み、前後の文脈も分析対象に含める

## 手順 1: 構造化

依頼文を次の 5 要素に分解し、各要素に「明記 / 推測可能 / 不明」のラベルを付ける。

- 上位目的: 何のためにやろうとしているか
- 手段: 何をしようとしているか
- 詰まり: どこで止まっているか
- 依頼: 相手（返信者）に何を求めているか
- 制約: 期限・権限・環境など

依頼文に複数の問題が混在している場合は、分けて列挙する。

## 手順 2: 不足診断

次の 7 観点を当てて、足りない情報を列挙する。該当しない観点は飛ばす。
この表を正とし、フェニックスチェックリスト原典の他の質問項目は持ち込まない。

| 観点 | 聞き方の例 |
|---|---|
| 上位目的 | それができると最終的に何をしたいですか？ |
| 未知の特定 | 具体的にどんなエラー文言・画面表示が出ていますか？ |
| 現状把握 | どの画面・コマンドで、どこまで進みましたか？ |
| 分解 | 詰まっているのは A と B のどちらですか？ |
| 境界 | ご自身の権限・環境でどこまで試せましたか？ |
| 前例 | 過去に同様の作業をした人や参考ドキュメントはありますか？ |
| 制約・期限 | いつまでに必要ですか？暫定対応でも大丈夫ですか？ |

上位目的を最優先で確認する。目的が分かると、詰まっている問題自体が不要になるケース
（別の手段で足りる等）を早期に潰せるため。

## 手順 3: 返信文案の作成

以下のルールで、そのまま Slack に貼れる返信文を書く。

- 「即答パート → 確認パート」の 2 部構成。今答えられることは先に答え、全部を質問で返さない。
  全部を質問で返すと「たらい回し感」が出て、相手の回答意欲が下がる
- 社内固有の情報（担当者名・社内ルール等）は、会話コンテキストや利用可能なツールから
  確実に分かる場合のみ使う。不確かなら勝手に埋めず `[要記入: ○○]` のプレースホルダを置く
- 確認パートの質問は優先度順に最大 3 問。それ以上投げると相手は答えない。
  入りきらない確認事項は返信文に入れず「内部メモ」に回す
- 仮説提示型で聞く（「おそらく〜だと思うのですが、〜ですか？」）。
  仮説があると回答コストが下がり、受け手の専門性が信頼を作る。
  仮説が立てられない場合のみ開いた質問にする
- 択一・Yes/No で答えられる形式を優先し、自由記述の質問は 1 問まで
- 相手の情報不足を指摘・非難しない。不足はこちらの質問設計で吸収する

## 出力フォーマット

必ずこの 4 部構成で出力する。

1. **構造化サマリ**: 5 要素 × ラベルの表
2. **不足診断**: 該当した観点と、欠けている情報
3. **返信文案**: そのまま貼れる形
4. **内部メモ**: 返信に入れなかった確認事項、原因の見立て等の仮説

推測で断定しない。分からないことは「不明」と書く。
